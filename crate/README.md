# crate

The desktop app for the music library, built with PySide6 and [PySide6-Fluent-Widgets](https://qfluentwidgets.com) (Fluent design; GPLv3), on top of [libcrate](../libcrate/README.md). It works on a libcrate catalog folder, the one holding `catalog.json` and `settings.yaml`.

```sh
uv run crate      # from the repo root
```

- **The catalog** sits at the top of the navigation bar, with its name (also in the window title). A click opens the catalog menu: the recent catalogs, the open one ticked (a click on another switches to it), then New catalog… and Open catalog…. Without a catalog open, the library page offers the same two as buttons. Switching is disabled while a scan or an enrich runs.
- **New catalog** asks for a music folder and a folder for its catalog (where `catalog.json`, `settings.yaml` and the thumbnails go; `~/music-metadata` is suggested), then creates it (`MetadataStore.init`: the default settings, then the first scan). **Settings from** (optional) copies another catalog's settings instead: its folder or its `settings.yaml`. A folder that holds a catalog already can't be picked: open it instead. When it's done, a notification points to the next step: turning on the fetchers you want in Settings › Fetchers.
- **Open** asks for a catalog folder only: the catalog knows its music folder. A folder without a catalog is refused. The catalog opened last is reopened on the next start.
- **Scan** reads new and changed files of the open catalog's music folder into it (`MetadataStore.scan`).
- **Enrich** runs the fetchers that are on in Settings › Fetchers (`MetadataStore.run`): first it downloads the models they need, then runs them in the order their inputs need (the genres and muq-mulan before llm-descriptions, which comes before description-bge). A fetcher that can't run (no API key, a fetcher it needs that's off) is left out, and a notification says why. With nothing on, a notification points to Settings; otherwise it takes you to the Jobs page, where it can be stopped. Closing the window stops it too, after the lookups in flight, saving what's done.
- The table searches artist, title, album and genres, and sorts by any column; each row shows the track's cover with its artists under the title, like Spotify (thumbnails are read from the files in the background, kept in memory and saved as small JPEGs in `thumbnails/` in the catalog folder, so each cover is decoded only once; thumbnails of changed or removed files are deleted), and the card on the right shows the selected track's cover (read from the file), tags, its description (with the keywords as chips, the lyrics' language, and whether the language model knew the track or described it from the facts), genres per source as chips, and audio.

- **Similar** (or right-click a track, Similar tracks) lists the tracks that sound most like the selected one (`libcrate.Similar`) on the **Similar** page: best match first, with a **Match** column (how alike each is, 100% for the selected track), and **Play** to play them in that order. It needs the tracks' embeddings, from the fetcher in Settings › Similar (`discogs-effnet` by default; turn it on in Settings › Fetchers, then press Enrich); without them a notification says so. Only embeddings made with the fetcher's current settings are used. Its settings (model, how many tracks, at most how many per artist, ...) are the `similar` section of the settings.
- **Right-click a track** in the library, or on the Similar, Describe or Radio page, to play it, list similar tracks, **Start radio** from it, or **Show in map**: the Map page opens with the track selected and in view (once the map is made; a notification says so when the track has no embedding for the map's model).

- **Map** shows the library's tracks laid out by how they sound (`libcrate.MusicMap`): similar-sounding tracks sit close together, coloured by cluster. Hover a dot for its title, click it to select it, double-click it to play it; the mouse wheel zooms, dragging moves the map, and a double-click on empty space shows it all again. **Play cluster** plays the selected track, then the rest of its cluster, nearest on the map first; **Similar** lists tracks similar to it, and **Radio** starts a station from it. The search box fades the tracks it doesn't match (artist, title, album), and Return selects the first match. The map is made in the background from the embeddings of the `map.embeddings` setting (default `discogs-effnet`), in `map.clusters` colours; it takes a few seconds and is saved next to the embeddings, so it's only made again when they or those settings change (opening the page checks).

- **Describe** lists the tracks that sound like a description: type something like "chill late-night electronic, with a warm bassline" and press Return. The best matches come first, with a **Match** column, and **Play** plays them in that order. It needs the tracks' CLAP embeddings (`describe.sound`, default `muq-mulan`: turn it on in Settings › Fetchers, then press Enrich, which downloads the model). Once the tracks have descriptions and their `description-bge` embeddings (`describe.words`; turn on `llm-descriptions` and `description-bge`), it matches those too and fuses the two rankings; the summary then names both, and **Match** is relative (100% for a track first in both). The model runs in a child process, loaded on the first description (several seconds) and kept until the window closes; its settings are the `describe` section.

- **Radio** plays an endless station: **Start radio** from a track's right-click menu, the Map's **Radio** button, or the Describe page, where it starts from the 10 best matches for the description. The station is made by `libcrate.Radio` from the `radio` section of the settings (embeddings, drift, choices, artist gap). The player always has 3 tracks queued after the current one, picked as it moves on. A track played to its end pulls the station towards it. A track skipped early (Next within 30 s, or within 40% of it) steers it away from tracks like it, and the queued tracks are picked again. The **Close / Wander** slider sets how far it drifts from where it started, for the tracks picked from then on. The page lists the station so far, with skipped tracks faded, the current one highlighted and the next ones after it; a double-click goes on from that track. **Stop** ends it, as does playing something else, and **Save as playlist** writes the tracks played through to an .m3u file.

- **Playing:** double-click a track (or select it and press Return) to play it with VLC, on the library or the similar page; the player bar at the bottom shows it with previous / play-pause / next and a seek bar, and Space plays and pauses. Next and previous follow the table's order when the track was started (its sort and search), and a finished track moves on to the next. **Shuffle** plays the rest of that queue in a random order (Previous goes back through it); the volume slider and mute button are on the right. Shuffle and volume are remembered between starts. It needs [VLC](https://www.videolan.org/vlc/) installed (`/Applications/VLC.app` on macOS), whose libvlc it uses through python-vlc.

**Jobs** (in the navigation bar; a dot on its icon while a scan or an enrich runs, with a tooltip saying which, and a red one after a job ended with problems, until the page is opened: a failure, a fetcher that gave up, or tracks that came to an error) lists this session's scans and enriches, newest first (the last 20): a card per job with when it ran and how it ended (done, stopped, failed and why), and a row per model download and fetcher, or the files of a scan, with its progress bar, tracks done out of those it had to do, and what they came to so far (found, not found, computed, downloaded, errors, already done; a scan's added, updated, removed, unchanged). A fetcher that gave up says why; steps that never started after a Stop say so. A running enrich's card has **Stop**: it finishes the lookups in flight and saves, and nothing after them starts.

**Settings** (in the navigation bar) edits the open catalog's settings file, `settings.yaml` in the catalog folder (a new catalog gets the defaults), a card per setting, described as in the file:

- **Fetchers**, with a tab per kind (Genres, Embeddings, Descriptions) and a section per fetcher: what it does, **Run on Enrich**, then its options. Under its description it says why it can't run (red: no API key, a fetcher it needs that's off or can't run), what it downloads on the next Enrich and how big that is, what it does without (an optional fetcher that's off), what uses it (features and other fetchers), and how far it is on the catalog: done, to redo (made with other settings), never done, failed, and with nothing to go on, and how many the next Enrich does. The problems follow the edits as they're made; how far it is follows the saved settings, worked out in the background when the page opens and after saving.
- **Services**: the API keys (by provider), the language model and its options, MusicBrainz and chosic.
- **Models**: the models folder, and each model with what it is, its size, whether it's downloaded, what it runs on and which fetchers that are on use it. **Download** fetches one (and what it runs on) in the background, **Delete** removes one after asking. Enrich downloads what it needs by itself; this is for doing it beforehand, or freeing the space.
- **Similar**, **Map**, **Describe**, **Radio**: each feature's settings; the embeddings it uses are dropdowns of the fetchers that fit, and a note says when one is off, so Enrich won't keep it up to date.

Save rewrites the file with its comments (readable only by you, since it can hold API keys), and the next Enrich uses it; comments added to the file by hand aren't kept.

The theme follows the system's light or dark mode until the **Theme** button at the bottom of the navigation bar switches it; that choice is remembered. The accent colour is `THEME_COLOR` in `crate/__init__.py`. Results and errors appear as notifications in the top right corner.

Scan and Enrich run in a background thread (`crate.tasks`), so the window stays responsive. Enrich works on a copy of the catalog and the table shows the result when it ends; progress is saved to `catalog.json` as it goes. The fetchers' settings (API keys, timeouts, models) come from the catalog's `settings.yaml`.

## Tests

```sh
uv run --package crate pytest crate      # from the repo root
```

They run Qt offscreen, so no window opens. The player tests play the FLACs in `test_music/` at the repo root (not in the repository; see [libcrate's tests](../libcrate/README.md#tests)) through libvlc with no sound output, and are skipped without VLC or that folder. They test the library page on its own: the main window (`MSFluentWindow`) is frameless and drives the native macOS window, which crashes on Qt's offscreen platform.
